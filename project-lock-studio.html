omarchy-lock-studio

Python web customizer for the Omarchy lock screen. Built 2026. Sole builder.

  • Python
  • QML
  • HTML/CSS/JS
  • PAM
  • Linux

What it does

A local web app (served on port 8731) that customizes the Omarchy lock screen: clock, profile with editable welcome line, dev quotes, MPRIS media display, background picker with automatic upscaling, theme and custom text colors, plus backup and restore. It generates LockView.qml while preserving the password field and PAM authentication.

It also now carries face unlock. omaFace's IR-camera PAM flow was ported into the generated view and service, so the lock screen I style is the same one that recognises me — the custom clock, quotes and background sit above a live face indicator, and the password always keeps working.

Hardest problem

A stale dev server once re-wrote a broken LockView.qml and killed the lock screen. The fix became process: relaunch the app (it takes over port 8731) before clicking Apply, and back up on every write.

The second was lock ownership. After installing a second lock plugin, my styled screen disappeared: the lock still engaged, it just showed a password field on a plain wallpaper, and nothing appeared in the logs. ext-session-lock grants exactly one owner per session, so when two plugins each ship a WlSessionLock the loser is ignored silently and no QML error is ever raised. I diagnosed it by fingerprinting the rendered layout (stock lock screens have no clock, profile or quotes), then resolved it by running a single locker: the face-unlock PAM flow and its status-file plumbing were ported into my own LockView.qml and Service.qml, the rival plugin was disabled, its post-update hook neutralised so an omarchy update cannot hand the lock back, and the generator template was patched so regenerating the view can't drop the ported code.

Outcome

My daily-driver lock screen, themed end to end and face-aware, with a safety net that makes experimenting free — and one owner of the session lock instead of two fighting for it.
